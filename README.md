# OBSERVER

Данное приложение помогает оператору SOC не только следить за аномалиями в сети, но и брать подсказки от LLM модели 
в режиме реального времени. В реальном времени оператор может взаимодейстовать с моделью

## Архитектура приложения

![Архитектура](/pictures/architecture.jpg)

### Бэкенд

Бекенд представляет из себя посредника, который принимает команды от фронтенд-клиента и передает их mcp-серверу, который тот в свое
время передает запрос локальной LLM-модели. Также, когда будет дан ответ от бекенда, то мы будем переделывать ответ под нужный
формат, также сохранять логи в базе данных, чтобы потом пользователь мог просмотреть краткую выжимку о логе от ИИ.

Бекенд работает на `node.js`, использует библиотеку `express`

### Фронтенд

Фронтенд сделан на React с использованием внутреннего стейт менеджера `Redux toolkit`. Есть нескольно страниц: страница с общением ллм-ки, страница с со всеми логами.

### Сборка и запуск приложения
1) Сначала надо установить (docker)[https://www.docker.com/]
2) Запускаем `zeek-mcp`:
2.1) Устанавливаем зависимости в python
```bash
python -m venv venv
source venv/bin/activate    # Linux/macOS
venv\Scripts\activate     # Windows
pip install -r requirements.txt
```
2.2) Запускаем mcp-сервер:
```bash
python Bridge_Zeek_MCP.py --mcp-host 127.0.0.1 --mcp-port 8081 --transport sse
```

* `--mcp-host`: Host for the MCP server (default: `127.0.0.1`).
* `--mcp-port`: Port for the MCP server (default: `8081`).
* `--transport`: Transport protocol, either `sse` (Server-Sent Events) or `stdio`.

3) Запускаем backend-приложения(локально):
  - `npm i`, устанавливаем зависимости
  - `npm run start`, бекенд запустится на порту: (127.0.0.1:3000)[https://127.0.0.1:3000]

4) Запускаем frontend-приложения(локально): 
  - `npm i`, устанавливаем зависимости
  - `npm run dev`, frontend запускается на этом порту: (127.0.0.1:5173)[https://127.0.0.1:5173]
